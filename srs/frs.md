# Функциональные требования

| ID требования | Название таска | Условие | Результат |
| :--- | :--- | :--- | :--- |
| **FR-01** | `[TSK_01]` Отобразить главный экран | 1. При нажатии кнопки "Войти" вызвать переход к `[TSK_03]`.<br>2. При нажатии кнопки "Зарегистрироваться" вызвать переход к `[TSK_02]`. | Отображение кнопок "Войти" и "Зарегистрироваться". |
| **FR-02** | `[TSK_02]` Регистрация в системе | Пользователь заполняет поля (Имя, email, Пароль, Телефон) и выбирает роль (Клиент или Юрист) через графический элемент, затем нажимает «Зарегистрироваться». | 1. Система генерирует уникальный ID и пишет данные в БД.<br>2. **Успех**: переход к `[TSK_04]` «Выбор специализации».<br>3. **Ошибка**: если логин занят, выводится «Логин занят» и возврат к форме.<br>4. В поле пароля доступно маскирование.<br>5. После авторизации считывается роль и идет редирект в Личный кабинет.<br>6. На email уходит письмо:<br>• *Тема*: Успешная регистрация в Law Guard<br>• *Текст*: "Здравствуйте! Вы успешно зарегистрированы. Ваш логин: {-----}. Для входа в личный кабинет перейдите по ссылке: {link}. С уважением, команда Law Guard." |
| **FR-03** | `[TSK_03]` Публикация запроса и выбор тарифа | **Вход из формы «Создать заявку»:**<br>• `service_type` (выбор категории)<br>• `request_description` (текст проблемы)<br>• `cost` (желаемая цена)<br>• `tariff_plan` (выбор условий)<br><br>**Логика валидации (Gateway):**<br>Проверка заполнения полей: `${request_description != null && cost > 0}`. | • **Ветка «Нет»:** Ошибка «Заполни описание и цену», возврат к форме.<br>• **Ветка «Да»:** Автозаполнение `request_status = 'open'` и `created_at`. Запись (INSERT) в таблицу `05.5_requests`. Вывод экрана: «Ваша заявка №[ID] успешно опубликована». |
| **FR-04** | `[TSK_04]` Подбор юриста и назначение исполнителя | **Сценарий отклика (SLA):**<br>Установка таймера ожидания на 3 часа для свободного отклика юристов.<br><br>**Логика назначения исполнителя:**<br>1. Автоматическая (отклик юриста).<br>2. Ручная эскалация (Admin Escalation), если через 3 часа исполнитель не найден. | • **При автоотклике:** Статус заявки ➔ `in_progress`, в поле `lawyer_id` записывается ID юриста.<br>• **При эскалации:** Создается User Task для Администратора. Админ принудительно назначает активного юриста из таблицы, его ID пишется в базу. |
